## 1. 本次改动

### 文档模型与解析
- `Core/JSONTree.swift`
  - `JSONTreeNode` 新增 `xmlElement` / `xmlText`，与 JSON 共用一棵树。
  - Base64 PDF/图片的字节数、长度判断全部改 `utf8.count`（O(1)），不再对 1.6MB 字符串做 Character 计数。
- `Core/DocumentTree.swift`（新增）
  - `XMLTreeParser`（Foundation XMLParser，SAX，一次构建，支持属性、CDATA、实体）。
  - `PayloadClassifier`：前缀快判 PDF/图片/JSON/XML/URL/文本，不做全量解析。
  - `DocumentTreeBuilder`：JSON/XML 统一入口；`JSONTreePresentation` 只解析一次。
  - `DocumentSerializer`：单遍字节级 Pretty 输出，保留 key 顺序/数字字面量，base64 媒体用占位符；不调用 `JSONSerialization`，不再逐 Character 拼接。
- `Core/PDFExtractor.swift`
  - 去掉整段 `JSONSerialization`，改用有序树遍历；只对候选字符串解码；总解码上限 32MB。

### 树渲染
- `Views/JSONTreeView.swift`
  - 新增 `embeddedJSON` / `embeddedXML` / XML 元素/属性/文本行；嵌套 JSON/XML 在原位置展开。
  - 任意深度的 base64 PDF/图片仍以内联卡片显示。
  - 小载荷（≤256KB）默认展开；大载荷（如 1.66MB `<content>`）默认折叠、点击后后台解析。
  - 迭代解析嵌套载荷并展开到媒体所在路径。
  - 工具栏：搜索（键/值预览，防抖）、全部展开/折叠、行数。
  - 右键：复制值/键名/路径、打开 URL。
  - 性能：静态颜色、Canvas 缩进、`Equatable`（按 presentation id）避免无关状态重算；PDF/图片缓存带 32MB `totalCostLimit`。
  - `JSONTreePresentation` 记录 `estimatedBytes`，供内存预算使用。

### 响应管线与内存
- `Store/AppStore.swift`
  - 发送/历史只解析一次文档树；Pretty 懒生成（后台，用户切到 Pretty 时才生成）。
  - 历史 payload 不再预生成 Pretty/重复解析 PDF。
  - 重载荷预算：最多保留 2 个重响应（当前 + 最新），其余释放 text/pretty/tree，保留 `result.body`；切回后台重建（约 53ms/1.7MB）。
  - 代码片段状态移出 `RequestTab`，避免响应视图跟着重算。
  - Mock 文本编辑的服务器同步改为 300ms 防抖。
- `Store/RequestTab.swift`
  - `ResponseRecord` 增加 `isEvicted` / `estimatedBytes`；新增 Pretty/恢复状态。
- `Views/ResponseView.swift`
  - Preview 同时支持 JSON/XML；Raw/Pretty 使用新文本组件；恢复/生成中显示状态；树视图 `.equatable()`。
- `Views/CodeText.swift`
  - 只读/编辑均改用 TextKit 2；软换行/行数估算在后台完成。
  - 只读大文本按行数估算文档高度，避免整篇布局；超长 base64 行自动软换行。
  - 编辑器：150ms 防抖回写、`focusToken` 自动聚焦、补全只看 caret 前 240 字符、大文本/大粘贴跳过补全与高亮、多行大文本按行数扩展可滚动区域。
  - `CodeTextView.maxDisplayBytes`：Raw 显示上限 1MB，超出显示说明；完整内容仍可 Copy/Save。
- `Views/WorkspaceView.swift`
  - 响应视图按 `tab.id` 重建，切标签释放上一个标签的 TextKit 视图。

### 交互修复

## 4. 2026-10-26 补丁：base64 PDF 内联卡片布局反馈循环（100% CPU 卡死）

### 现象与证据
- 用户打开多个 Demo Mock/base64 请求后卡死：进程 100% CPU，physical footprint 136.4MB（峰值 319MB）。
- `sample 28529 5`：主线程全部停留在 SwiftUI 布局（`ViewLayoutEngine.sizeThatFits` / `GeometryReaderLayout` / `LazyLayoutViewCache.updateItemPhases`），并出现 `_NSViewLayoutFeedbackLoopDebugger willSendSetNeedsLayoutToLayerOfView:`；这是布局反馈循环，不是解析或网络阻塞。
- 截图确认画面停在 `resp_1` 的 PDF 内联卡片；卡片图片溢出滚动内容，树文档高度只有 384pt。
- 复现器（1728×1084 真实 zoom、加载 `resp_1`、滚动到 PDF 卡片）：修复前树滚动文档高 384、`maxY=220`，PDF 卡片被裁切且布局 CPU 持续升高。

### 根因
`PDFInlineCard` / `ImageInlineCard` 的预览使用：

```swift
Image(nsImage:)
  .resizable()
  .scaledToFit()
  .frame(maxWidth: .infinity)
  .frame(maxHeight: 400)
```

在 `LazyVStack` 行内，图片宽度提案与行/文档高度测量互相影响；加载占位高度 120pt，图片加载后变为 400pt 但滚动文档高度没有同步增长，触发 SwiftUI/AppKit 布局反馈循环，窗口越宽越容易触发。

### 修复
`Sources/PostmanSwift/Views/JSONTreeView.swift`：
- PDF 预览固定 `300×400`，图片预览固定 `320×260`，加 `.clipped()`。
- 加载占位高度分别改为 `400` / `260`，与加载完成后一致，避免行高跳变。
- 不再在媒体卡片内使用 `frame(maxWidth: .infinity)`，行高成为确定值，LazyVStack 可稳定测量。

### 修复后验证
- 全屏 1728×1084（真实 `window.zoom`，先加载请求再铺满）：
  - `resp_1`：树文档高 1243/1399，滚动到底 `maxY=906/1062`；6 秒内主线程最大停顿 **19.4ms**，CPU 1.97s（非持续 100%），footprint 65.5MB。
  - `base64_json`（PDF+PNG）：文档高 890，滚动到底 `maxY=553`；3 秒内最大停顿 **29.6ms**，CPU 2.63s。
  - 切回 `resp_1`：最大停顿 **19.4ms**；无卡死、无 crash。
- `swift test`：54 tests 全部通过；release 重建 8.2MB。
- 已删除临时 `FullscreenQAHarness`；release 中无 QA harness 代码。
- 原始 hang sample：`/tmp/pn-hang-20261026-0708.txt`；修复后截图：`/tmp/pn-fullscreen.png`。

> 用户当前仍开着的卡死实例不会自动更新；需退出后重新打开 `dist/PostmanSwift.app`。

### 2026-10-26 最终修复：移除小树的 LazyVStack 测量路径
- 复现：开启 Mock Server → 发送 `Mock · Demo Mock` 最后 3 个请求（`/base64_json`、`/json_in_json`、`/resp_1`）→ 全屏滚动响应，必现 100% CPU；采样主线程停在 `LazyStack<>measureEstimates` / `LazyLayoutViewCache`，即使把所有媒体卡片固定尺寸后仍会触发。
- 修复（`Sources/PostmanSwift/Views/JSONTreeView.swift`）：
  - 行数 ≤600 的树改用普通 `VStack` 渲染；只有真正的大规模展开（>600 行）才使用 `LazyVStack`。这直接移除了卡死采样中的懒布局测量路径。
  - PDF/图片卡片默认**折叠**，只有用户点开时才加载/渲染页图；卡片高度在所有状态严格一致（加载/成功/失败同高，底部动态提示行已移除）。
- 验证（真实 UI，Mock Server 运行中，1728×1084 全屏）：
  - 依次发送并滚动 `/base64_json`、`/json_in_json`、`/resp_1`（16/90/38 行），再展开 PDF 卡片：
    - `feedback-loop=0`，`LazyStack.measureEstimates=0`；
    - 空闲 CPU 采样主线程为空闲事件循环，physical footprint ≈ **119MB**；
    - 无卡死、无崩溃。
  - `swift test`：54 tests 全绿；release 8.2MB。

## 5. 已知取舍 / 后续可选项
- Raw/Pretty 显示上限 1MB（Raw），超出显示说明；完整响应仍可通过头部 Copy/Save 获取，Preview 展示完整结构。这是为内存与首屏速度做的边界。
- 大于 256KB 的嵌套载荷默认折叠，点击后异步解析；1.66MB `<content>` 的展开路径与已验证的 presentation 构造使用同一解析/flatten 代码。
- 代码片段为窗内浮层（非系统 sheet），因此没有系统 sheet 的 0.3s 动画；如需严格模态键盘焦点，可后续补 `Esc` 全局处理（当前 `onExitCommand` + Close 已可用）。
- XML 属性顺序按解析器稳定排序（名称），内容与层级不受影响。
